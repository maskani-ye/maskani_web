# الحارسان البصريّان — لماذا خارج `prebuild`

`audit:wrap` و`audit:contrast` يقيسان **الصفحة المرسومة**: يشغّلان متصفّحاً
حقيقياً ويقرآن اللون المحسوب وعدد أسطر النصّ. ولهذا لا يعملان في `prebuild`:
يحتاجان خادماً يعمل (`npm run start`) وبناءً جاهزاً — فوضعهما هناك يجعل البناء
يعتمد على نفسه.

```bash
npm run build && npm run start &     # ثمّ
npm run audit:visual                  # أو على الإنتاج:
AUDIT_BASE=https://maskani.homes npm run audit:visual
```

## ما يمسك كلٌّ منهما — ولماذا لم يمسكه غيره

**`audit:wrap`** — زرٌّ ينكسر نصّه إلى سطرين. يقيس بـ`Range` على العقدة
النصّية (نصٌّ مكسور = مستطيلان)، لا بارتفاع الزرّ: زرٌّ فيه أيقونة 20px بجانب
نصٍّ سطره 14px يبدو «سطرين» في حساب الارتفاع وهو سطرٌ واحد بالعين — أوّل
نسخةٍ من هذا المقياس أبلغت عن **143 زرّاً وكلّها سليمة**.

**`audit:contrast`** — نصٌّ لا يُقرأ على خلفيته. أمسك عطلاً لا تراه الشيفرة
إطلاقاً: `tailwind-merge` كان **يبتلع `text-white`** لأنّ سُلَّمنا يسمّي
المقاسات بأدوارها (`text-body`) فتُصنَّف لون نصّ — فكل زرّ `bg-primary` يصل
المتصفّح بنصٍّ بلون `ink`، تباينه 1.11:1. `text-white` مكتوبٌ في الملفّ
وموجودٌ في CSS ومفقودٌ من العنصر المرسوم وحده.

## ⚠️ نطاق المسح جزءٌ من النتيجة

`AUDIT_PAGES` تُحدّد ما يُفحص، وافتراضها بضع عشرة صفحة. **«أخضر» على عشرين
صفحة لا يعني الموقع** — فيه 5,483 عنواناً. لمسحٍ شامل خُذ شكلاً واحداً لكل
مسار من خريطة الموقع (69 شكلاً)، فذلك ما كشف زرّين في صفحات التفاصيل بعد أن
أُعلن «صفر» على مسحٍ أضيق.
